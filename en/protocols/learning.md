# Protocol — Learning loop (consolidation)

> Not loaded by default. **Automatic**:
> - **trigger**: `session.sh close` shows « Unconsolidated observations: N » when the `OBSERVATIONS.md` entries without a marker (`[proposed …]`, `[graduated]`, `[dismissed …]`) reach the threshold (20 by default, `CONTINUUM_OBS_THRESHOLD`) → the agent that closes runs the loop at once, without asking (`AGENTS.md` §3.3). `open` shows the same signal, for information. Also on direct request (« run the learning »).
> - **no « yes » to wait for**: what the loop deduces is active as soon as it is written, marked `[auto YYYY-MM-DD — not announced]`, announced to the user (right away if they are there, otherwise at the next opening, `AGENTS.md` §1.6), then marked `announced YYYY-MM-DD`.
> - **objection**: the user says something learned bothers them → removed at once (step 9).
> Why automatic: a loop that waits for someone to think of running it, then for each rule to be validated, does not run in practice — seen while Continuum was being built: 74 observations left pending in three days. Control happens afterwards, by objection — a learning is reversible.

All the steps below are **rewrites** of shared files: always under lock (`bash tools/session.sh lock take` … commit on the paths touched … `lock release`, `AGENTS.md` §3). Long work: `lock take` again renews the expiry. A harness that can delegate (sub-agent): hand it the reading of `OBSERVATIONS.md`, only the result comes back. The mechanical part (end-of-session appends, `BASE.md` caps) is done by `tools/consolidate.sh`, not here.

1. Reread the entries without a marker in `OBSERVATIONS.md`.
2. **Sort first**: an entry that is not an observation of behavior (event, system fact, action of the agent — definition `AGENTS.md` §2) → marked `[dismissed: event]` on its `**[date]**` line, never deleted. It no longer counts toward the threshold. Without this sorting, an automatic loop turns noise into rules.
3. **Group** — first the `[lesson]` entries that describe the same situation → action (same trigger, same gesture, different wording), then the `[incident]`/`[success]` entries without a lesson, by pattern (the agent's judgment, not text matching). A pattern confirmed over **3 distinct sessions** (not 3 times in the same one) crosses the threshold. An `[AI]` entry alone never counts as a confirmation. A pattern already removed on objection (`[dismissed: objection …]` entries) is never proposed again.
4. **A lesson that matches an already active directive**: nothing new is created. It reconfirms it, and since it comes from an incident, it also says the directive **was not followed** → in its Basis, a counter « not followed: N (last YYYY-MM-DD) »; entries marked `[proposed → DIRECTIVES.md]`. At N = 3: the directive is **ineffective** (written but not applied) → reworded more concretely, as « When … → do … », applied outright and announced as a revision (step 7). It is the most direct signal of what does not work.
   **A lesson specific to a project** (its infrastructure, its code): in the project's `CHANGELOG.md`, not in `DIRECTIVES.md`; entry marked `[dismissed: project → NN_Project/CHANGELOG.md]`.
   **Threshold reached, new pattern that calls for a behavior of the agent** → directive written directly in `DIRECTIVES.md` §Active › **Learned (automatic)**, as « When <situation> → do <action> » when possible, with its **Basis** (sessions/dates of the confirmations, 2-3 lines, never a narrative pile-up) and `[auto YYYY-MM-DD — not announced]`. Original entries marked `[proposed → DIRECTIVES.md]`. Reconfirmation of an already active directive: counter + most recent date in its Basis, without lengthening the text nor a new announcement.
5. **Threshold reached, pattern that describes the user without prescribing anything** (how they check, decide, design) → `TRAITS.md` (statement + Basis, `[auto … — not announced]`), entries marked `[graduated]`.
6. **Stated facts** (`[fact]`, said directly by the user) → `PROFILE.md`: new fact added (`[auto … — not announced]`), contradicted fact replaced, nothing historical. No threshold: a direct fact is enough once. Entries marked `[graduated]`.
7. **Going back**: an observation that contradicts an active directive or a trait → revision or removal applied directly, the old text moved as is into `_archive/<date>_revisions.md`, announced like an addition (`not announced`). The user can refuse: the old text comes back.
8. **Effects**: count the `[effect] <directive>` entries in the logs of `sessions/sealed/` since the last loop. In the summary (« what have you learned? »): directives never followed by any effect.
9. **Objection** (« that bothers me », « remove that », « no » to an announced addition), at any time: removed at once, under lock — the entry moved as is into `_archive/<date>_objections.md` with the user's words; the original observations marked `[dismissed: objection YYYY-MM-DD]`. No discussion, no counter-argument (unless they ask for one).
10. **Announce**: user still there → tell them the additions, one line each (what, over how many sessions), and switch the markers to `announced`. Otherwise, the next opening takes care of it (`AGENTS.md` §1.6).

`BASE.md`: fixed caps (§History 5 entries, §Decided 5), applied automatically at every merge — nothing to do here. Without a cap, a file reread at every startup grows until it costs more than it brings.
